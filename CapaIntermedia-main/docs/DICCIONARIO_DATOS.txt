- El correo debe ser único en el sistema
- La edad mínima para registro es de 12 años

├─────────────────┼──────────────┼──────────────────────────┼────────────────────────────────────────────┼────────────────────────┤

│                 │              │                          │                                            │ NOT NULL               │
├─────────────────┼──────────────┼──────────────────────────┼────────────────────────────────────────────┼────────────────────────┤
│ Titulo          │ VARCHAR(255) │ 1-255 caracteres         │ Título de la publicación                   │ NOT NULL               │
├─────────────────┼──────────────┼──────────────────────────┼────────────────────────────────────────────┼────────────────────────┤

│                 │              │ 2 (Aprobada)             │ 1=Pendiente aprobación, 2=Aprobada,        │                        │

├─────────────────┼──────────────┼──────────────────────────┼────────────────────────────────────────────┼────────────────────────┤
│ TipoMultimedia  │ VARCHAR(50)  │ MIME types:              │ Tipo de contenido multimedia               │ NOT NULL               │
│                 │              │ "image/jpeg",            │                                            │                        │

Reglas de Negocio:
- Las publicaciones inician con Estatus = 1 (Pendiente)
- Solo usuarios administradores pueden cambiar el estatus
- Trigger TRG_ActualizarFechaAprobacion actualiza automáticamente Fec_aprob cuando Estatus cambia a 2
- FK: ID_Categ referencia a categoria con ON UPDATE CASCADE
- FK: ID_User referencia a usuario con ON UPDATE CASCADE
- FK: ID_Mundial referencia a mundial con ON DELETE SET NULL, ON UPDATE CASCADE

TABLA 6: usuario_reaccion
═══════════════════════════════════════════════════════════════════════════════
Descripción: Registra las reacciones (likes) de los usuarios sobre las
publicaciones. Implementa una relación muchos a muchos entre usuario y
publicación.

┌─────────────────┬──────────────┬──────────────────────────┬────────────────────────────────────────────┬────────────────────────┐
│ CAMPO           │ TIPO DE DATO │ DOMINIO                  │ DESCRIPCIÓN                                │ RESTRICCIONES          │
├─────────────────┼──────────────┼──────────────────────────┼────────────────────────────────────────────┼────────────────────────┤
│ ID_User         │ INT(11)      │ ID válido de usuario     │ Usuario que dio la reacción                │ PK (compuesta),        │
│                 │              │                          │                                            │ FK → usuario(ID_User)  │
│                 │              │                          │                                            │ NOT NULL               │
├─────────────────┼──────────────┼──────────────────────────┼────────────────────────────────────────────┼────────────────────────┤
│ ID_Publi        │ INT(11)      │ ID válido de publicación │ Publicación que recibió la reacción        │ PK (compuesta),        │
│                 │              │                          │                                            │ FK → publicacion       │
│                 │              │                          │                                            │ (ID_Publi), NOT NULL   │
├─────────────────┼──────────────┼──────────────────────────┼────────────────────────────────────────────┼────────────────────────┤
│ Estatus         │ CHAR(1)      │ 'L' (Like)               │ Tipo de reacción. Actualmente solo         │ NOT NULL, DEFAULT 'L'  │
│                 │              │                          │ se usa 'L' para likes                      │                        │
└─────────────────┴──────────────┴──────────────────────────┴────────────────────────────────────────────┴────────────────────────┘

Reglas de Negocio:
- Un usuario solo puede dar un like por publicación
- Si se vuelve a ejecutar toggle, se elimina el registro (unlike)
- PK compuesta (ID_User, ID_Publi) garantiza unicidad
- FK: ID_User referencia a usuario con ON DELETE CASCADE, ON UPDATE CASCADE
- FK: ID_Publi referencia a publicacion con ON DELETE CASCADE, ON UPDATE CASCADE

Reglas de Negocio:
- Cada combinación usuario-publicación se registra solo una vez
- Se usa INSERT IGNORE para evitar duplicados
- PK compuesta (FK_PUBLICACION, FK_USUARIO) garantiza unicidad
- FK: FK_PUBLICACION referencia a publicacion
- FK: FK_USUARIO referencia a usuario
